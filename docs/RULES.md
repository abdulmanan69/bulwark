## composite

Combinations. Each component is individually reasonable; the exposure exists only in how they fit together.

### BW-CMP-001

**Agent combines private data, untrusted input and an outbound channel**

`severity: CRITICAL`  `confidence: MEDIUM`

This agent can simultaneously (1) reach data that would not be published, (2) ingest content that someone outside the organisation wrote, and (3) send bytes to a destination outside the trust boundary. Each is a reasonable capability. Together they are a complete exfiltration path that needs no vulnerability to exploit: attacker-authored text arrives through the ingestion tool as data, the model reads it as instructions, and the outbound tool carries the private data away. A model following instructions found in content is the intended behaviour, which is why no patch closes this -- only removing one of the three legs does.

**How to fix.** Break one leg for any session that needs the other two. In practice: split the work across two agents with different tool sets; restrict the outbound tool to an allow-listed destination; or route the ingestion tool through `bulwark proxy` so fetched content is scanned and quarantined before it reaches the context window.

**Maps to.** `CWE CWE-200` Exposure of Sensitive Information, `CWE CWE-829` Inclusion of Functionality from Untrusted Control Sphere, `EU-AI-ACT EUAIACT.ART15` Accuracy, robustness and cybersecurity, `MITRE-ATLAS AML.T0051` LLM Prompt Injection, `MITRE-ATLAS AML.T0024` Exfiltration via ML Inference API, `MITRE-ATLAS AML.T0025` Exfiltration via Cyber Means, `NIST-AI-600-1 NIST.GAI.DATA` Data privacy, `NIST-AI-600-1 NIST.GAI.INFO` Information security, `OWASP-LLM-2025 LLM01` Prompt Injection, `OWASP-LLM-2025 LLM02` Sensitive Information Disclosure, `OWASP-LLM-2025 LLM06` Excessive Agency

**References.** https://atlas.mitre.org/techniques/AML.T0024

### BW-CMP-002

**Two servers expose tools with colliding names**

`severity: HIGH`  `confidence: HIGH`

Two connected servers publish tools with the same or near-identical names. The model chooses between them from the description alone, so a newly added server can quietly capture calls the user believes are going to the established one. A name that differs only by a look-alike character or an underscore is not a coincidence.

**How to fix.** Rename or disconnect one of the servers. Where the host supports namespacing, enable it so the model sees a qualified name. Confirm which server a colliding name belongs to before using either.

**Maps to.** `CWE CWE-345` Insufficient Verification of Data Authenticity, `CWE CWE-829` Inclusion of Functionality from Untrusted Control Sphere, `MITRE-ATLAS AML.T0053` LLM Plugin Compromise, `OWASP-LLM-2025 LLM01` Prompt Injection, `OWASP-LLM-2025 LLM03` Supply Chain

### BW-CMP-003

**Tool description gives instructions about another server's tools**

`severity: CRITICAL`  `confidence: HIGH`

A tool description names a tool belonging to a different server and tells the model how to treat it. A server has no legitimate knowledge of what else is connected: describing a peer's tools means the description was written to manipulate the model's routing, not to document this tool. This is how one compromised server redirects, disables or wraps the tools around it.

**How to fix.** Disconnect the server that references its peers. Nothing about a correct integration requires it.

**Maps to.** `CWE CWE-345` Insufficient Verification of Data Authenticity, `MITRE-ATLAS AML.T0053` LLM Plugin Compromise, `MITRE-ATLAS AML.T0051` LLM Prompt Injection, `OWASP-LLM-2025 LLM01` Prompt Injection, `OWASP-LLM-2025 LLM03` Supply Chain

### BW-CMP-004

**Single tool concentrates disproportionate capability**

`severity: HIGH`  `confidence: MEDIUM`

One tool combines several high-power capabilities -- executing commands, deleting files, reaching credentials, changing infrastructure or moving money. A tool that can do all of these is indistinguishable, from the model's point of view, from a shell: there is no meaningful approval decision left to make, because approving it once approves everything.

**How to fix.** Split the tool into narrower operations so each call can be judged. Where the tool is third-party, restrict it at the boundary instead: `bulwark proxy --deny-tool` removes individual operations from the surface the model sees.

**Maps to.** `CWE CWE-250` Execution with Unnecessary Privileges, `CWE CWE-269` Improper Privilege Management, `EU-AI-ACT EUAIACT.ART14` Human oversight, `MITRE-ATLAS AML.T0011` User Execution, `OWASP-LLM-2025 LLM06` Excessive Agency

### BW-CMP-005

**Dangerous tool is pre-approved in configuration**

`severity: CRITICAL`  `confidence: HIGH`

The configuration lists this tool as auto-approved, so the host will call it without prompting. The tool can execute commands, delete data, reach credentials or move money. Pre-approval is reasonable for a read-only lookup; for these operations it removes the only control that stands between injected text and an irreversible action.

**How to fix.** Remove the tool from the auto-approve list. If the friction is the problem, pre-approve a narrower tool instead of a broader one.

**Maps to.** `CWE CWE-250` Execution with Unnecessary Privileges, `CWE CWE-284` Improper Access Control, `EU-AI-ACT EUAIACT.ART14` Human oversight, `MITRE-ATLAS AML.T0011` User Execution, `NIST-AI-600-1 NIST.GAI.HUMAN` Human-AI configuration, `OWASP-LLM-2025 LLM06` Excessive Agency

### BW-CMP-006

**Server with weak provenance holds high-privilege tools**

`severity: HIGH`  `confidence: MEDIUM`

This server's code is not pinned, not reviewed, or fetched at launch, and the tools it exposes can execute commands, reach credentials or change infrastructure. Weak provenance is tolerable for a calculator. Combined with this much authority, the next upstream publish is a remote code execution on every machine that runs the agent.

**How to fix.** Pin the server to a reviewed version before granting it these tools, or move the high-privilege operations to a server you control.

**Maps to.** `CWE CWE-494` Download of Code Without Integrity Check, `CWE CWE-250` Execution with Unnecessary Privileges, `MITRE-ATLAS AML.T0010` ML Supply Chain Compromise, `MITRE-ATLAS AML.T0011` User Execution, `NIST-AI-600-1 NIST.GAI.SUPPLY` Value chain and component integration, `OWASP-LLM-2025 LLM03` Supply Chain, `OWASP-LLM-2025 LLM06` Excessive Agency

## drift

The present compared against a pinned past. The only way to detect a change made after approval.

### BW-DRF-001

**Tool definition changed after it was pinned**

`severity: CRITICAL`  `confidence: HIGH`

A model-visible string differs from the version recorded in bulwark.lock. The configuration did not change, so nothing in code review or version control would show this: the server simply returned different text on the next connection. That is the rug pull -- behave correctly while being evaluated, change afterwards -- and it is the single failure mode that static configuration review cannot detect by construction.

**How to fix.** Do not re-pin until the change is explained. Compare the before and after text, check the upstream release notes for a version that matches, and if there is no published change that accounts for it, disconnect the server. Once satisfied, `bulwark pin` records the new state deliberately.

**Maps to.** `CWE CWE-345` Insufficient Verification of Data Authenticity, `CWE CWE-494` Download of Code Without Integrity Check, `ISO-42001 ISO42001.A.6.2.4` AI system verification and validation, `MITRE-ATLAS AML.T0053` LLM Plugin Compromise, `MITRE-ATLAS AML.T0031` Erode ML Model Integrity, `NIST-AI-600-1 NIST.GAI.SUPPLY` Value chain and component integration, `OWASP-LLM-2025 LLM01` Prompt Injection, `OWASP-LLM-2025 LLM03` Supply Chain, `OWASP-LLM-2025 LLM04` Data and Model Poisoning

### BW-DRF-002

**No lockfile, so tool definitions are unverifiable**

`severity: MEDIUM`  `confidence: HIGH`

There is no bulwark.lock recording what the connected servers were approved to say. Without it, a server can change its tool descriptions at any point after review and nothing will notice: there is no prior state to compare against. This is the agent-stack equivalent of installing dependencies with no lockfile, except that the thing that changes is an instruction to a model rather than a function body.

**How to fix.** Run `bulwark pin` once the current configuration has been reviewed, commit bulwark.lock, and add `bulwark verify` to CI so any later change has to be approved in a pull request.

**Maps to.** `CWE CWE-345` Insufficient Verification of Data Authenticity, `ISO-42001 ISO42001.A.6.2.4` AI system verification and validation, `NIST-AI-600-1 NIST.GAI.SUPPLY` Value chain and component integration, `OWASP-LLM-2025 LLM03` Supply Chain

## hooks

Shell commands the host runs automatically on agent events -- the highest-privilege extension point in the stack.

### BW-HOOK-001

**Hook executes a dangerous command automatically**

`severity: CRITICAL`  `confidence: HIGH`

A hook is a shell command the host runs on its own when an agent event fires -- no model decision, no approval prompt, no tool-call record. That makes hooks the highest-privilege extension point in the stack, and this one performs an action that would be alarming even with a human in the loop.

**How to fix.** Review who added the hook and why. Replace ad-hoc commands with a reviewed script committed to the repository, and treat any hook that reads credentials or calls out to the network as an incident until proven otherwise.

**Maps to.** `CWE CWE-78` OS Command Injection, `CWE CWE-77` Command Injection, `CWE CWE-200` Exposure of Sensitive Information, `MITRE-ATLAS AML.T0011` User Execution, `MITRE-ATLAS AML.T0025` Exfiltration via Cyber Means, `NIST-AI-600-1 NIST.GAI.INFO` Information security, `OWASP-LLM-2025 LLM06` Excessive Agency, `OWASP-LLM-2025 LLM02` Sensitive Information Disclosure

### BW-HOOK-002

**Hook interpolates agent-controlled data into a shell command**

`severity: HIGH`  `confidence: MEDIUM`

The hook command substitutes a variable that carries model or user-supplied text -- a prompt, a file path, a tool argument -- directly into a shell. Shell metacharacters in that text become part of the command, which turns any content the agent reads into a potential command-injection vector.

**How to fix.** Read hook input from stdin as JSON inside a script rather than interpolating it into the command string, and quote every expansion. Never build a shell command by concatenating agent-supplied text.

**Maps to.** `CWE CWE-77` Command Injection, `CWE CWE-78` OS Command Injection, `MITRE-ATLAS AML.T0051` LLM Prompt Injection, `OWASP-LLM-2025 LLM01` Prompt Injection, `OWASP-LLM-2025 LLM05` Improper Output Handling

### BW-HOOK-003

**Persistent instruction file contains an injected directive**

`severity: HIGH`  `confidence: MEDIUM`

A rules or memory file (CLAUDE.md, AGENTS.md, .cursorrules and equivalents) contains text that reads as an attack on the agent rather than as project guidance. These files load into every session automatically and are edited through ordinary pull requests, so they are the most durable place to leave an instruction and the least likely to be security-reviewed.

**How to fix.** Treat instruction files as security-relevant code: require review on changes, and diff them in CI with `bulwark scan --fail-on high`.

**Maps to.** `CWE CWE-94` Code Injection, `MITRE-ATLAS AML.T0051` LLM Prompt Injection, `MITRE-ATLAS AML.T0031` Erode ML Model Integrity, `OWASP-LLM-2025 LLM01` Prompt Injection, `OWASP-LLM-2025 LLM04` Data and Model Poisoning

## injection

Text that reaches the model. These rules ask one question of a tool description: is it describing a capability, or issuing an instruction?

### BW-INJ-001

**Tool description contains instructions aimed at the model**

`severity: CRITICAL`  `confidence: HIGH`

A tool description is documentation: it tells the model what a tool does so the model can decide whether to call it. This description instead issues directives -- overriding prior instructions, concealing behaviour from the user, naming credentials, or specifying where to send data. Because descriptions are loaded into context before any tool is called, the instruction executes as soon as the server is connected, whether or not the tool is ever used.

**How to fix.** Do not connect this server until the description is explained. Pin the server to a reviewed version, diff the tool definitions against that pin with `bulwark diff`, and run the server behind `bulwark proxy` so description changes are caught at runtime.

**Maps to.** `CWE CWE-77` Command Injection, `CWE CWE-829` Inclusion of Functionality from Untrusted Control Sphere, `MITRE-ATLAS AML.T0051` LLM Prompt Injection, `MITRE-ATLAS AML.T0053` LLM Plugin Compromise, `NIST-AI-600-1 NIST.GAI.INFO` Information security, `OWASP-LLM-2025 LLM01` Prompt Injection, `OWASP-LLM-2025 LLM06` Excessive Agency

**References.** https://owasp.org/www-project-top-10-for-large-language-model-applications/, https://atlas.mitre.org/techniques/AML.T0051

### BW-INJ-002

**Model-visible text hides characters a reviewer cannot see**

`severity: CRITICAL`  `confidence: HIGH`

The text contains codepoints that render as nothing -- Unicode Tag characters, zero-width spaces, bidirectional overrides, variation selectors or private-use characters. The model receives every one of them; a human reviewing the same string in an editor or a marketplace listing does not. There is no legitimate reason for a tool description to contain them, and the Unicode Tag block in particular maps one-to-one onto ASCII, so it can carry an entire hidden instruction inside a string that looks empty.

**How to fix.** Treat the artifact as compromised. Strip the invisible codepoints and compare what remains against what the publisher claims the tool does. Reject any component whose description needs invisible characters.

**Maps to.** `CWE CWE-94` Code Injection, `CWE CWE-345` Insufficient Verification of Data Authenticity, `MITRE-ATLAS AML.T0051` LLM Prompt Injection, `OWASP-LLM-2025 LLM01` Prompt Injection

### BW-INJ-003

**Instructions concealed in markup or layout padding**

`severity: HIGH`  `confidence: MEDIUM`

The text hides content using HTML comments, CSS that renders an element invisible, or whitespace padding that pushes the payload outside a reviewer's viewport. The model reads the raw string, so none of these mechanisms hide anything from it -- they hide it only from the person approving the component.

**How to fix.** Remove the concealed content, or reject the component. A description that needs an HTML comment is describing something it does not want reviewed.

**Maps to.** `CWE CWE-94` Code Injection, `MITRE-ATLAS AML.T0051` LLM Prompt Injection, `OWASP-LLM-2025 LLM01` Prompt Injection

### BW-INJ-004

**Encoded payload embedded in model-visible text**

`severity: HIGH`  `confidence: MEDIUM`

A base64 or hex blob in the text decodes to readable prose. Encoding prose serves no functional purpose in a description -- it defeats keyword review while remaining perfectly legible to a model that is asked to decode it.

**How to fix.** Decode the blob and judge the plaintext. If it reads as an instruction, treat the component as hostile.

**Maps to.** `CWE CWE-94` Code Injection, `MITRE-ATLAS AML.T0051` LLM Prompt Injection, `OWASP-LLM-2025 LLM01` Prompt Injection

### BW-INJ-005

**Model-visible text names an out-of-band collection endpoint**

`severity: CRITICAL`  `confidence: HIGH`

The text references a request-capture service (webhook.site, interact.sh, a tunnelling domain) or a markdown image whose URL carries a query string. A markdown image is fetched when the response renders, so a URL of the form https://host/?q=DATA exfiltrates whatever the model substitutes for DATA with no tool call, no approval prompt, and nothing visible in the transcript but a broken image.

**How to fix.** Remove the endpoint. If the component genuinely needs to call out, the destination belongs in configuration where it can be allow-listed and logged, not in text the model reads as an instruction.

**Maps to.** `CWE CWE-200` Exposure of Sensitive Information, `CWE CWE-598` Sensitive Data in Query String, `MITRE-ATLAS AML.T0024` Exfiltration via ML Inference API, `MITRE-ATLAS AML.T0025` Exfiltration via Cyber Means, `NIST-AI-600-1 NIST.GAI.DATA` Data privacy, `OWASP-LLM-2025 LLM01` Prompt Injection, `OWASP-LLM-2025 LLM02` Sensitive Information Disclosure

## permissions

What the agent may do without asking a human first.

### BW-PRM-001

**Permission rule grants a high-power tool without constraint**

`severity: HIGH`  `confidence: HIGH`

An allow-rule names a tool that can run commands or write files, but constrains nothing about how. Once such a rule exists the approval prompt stops appearing for that tool, which means any instruction the model follows -- including one injected through content it read -- executes without a human seeing it first.

**How to fix.** Narrow the rule to the specific commands or paths that actually need to be automatic, for example `Bash(git status:*)` rather than `Bash`. Keep the unconstrained form out of committed settings entirely.

**Maps to.** `CWE CWE-250` Execution with Unnecessary Privileges, `CWE CWE-269` Improper Privilege Management, `CWE CWE-284` Improper Access Control, `EU-AI-ACT EUAIACT.ART14` Human oversight, `MITRE-ATLAS AML.T0011` User Execution, `OWASP-LLM-2025 LLM06` Excessive Agency

### BW-PRM-002

**Permission rule pre-approves a dangerous operation**

`severity: HIGH`  `confidence: HIGH`

The allow-rule's argument authorises an operation that is destructive, escalates privilege, reaches credentials, or publishes data. These are precisely the operations a human should be asked about, and the rule removes the asking.

**How to fix.** Delete the rule. If the operation genuinely needs to be automatic, wrap it in a script with its own checks and allow only that script.

**Maps to.** `CWE CWE-250` Execution with Unnecessary Privileges, `CWE CWE-269` Improper Privilege Management, `CWE CWE-78` OS Command Injection, `EU-AI-ACT EUAIACT.ART14` Human oversight, `MITRE-ATLAS AML.T0011` User Execution, `OWASP-LLM-2025 LLM06` Excessive Agency, `OWASP-LLM-2025 LLM02` Sensitive Information Disclosure

### BW-PRM-003

**Settings disable the human approval step**

`severity: CRITICAL`  `confidence: HIGH`

A settings flag or default mode removes the confirmation prompt for tool calls. Every other control in an agent stack assumes a human is the last check before an irreversible action; this setting deletes that check globally, for every tool, including ones added later.

**How to fix.** Remove the flag from committed settings. If a sandboxed CI run truly needs it, set it there via an environment variable on the runner, never in a file that a developer machine also reads.

**Maps to.** `CWE CWE-250` Execution with Unnecessary Privileges, `CWE CWE-284` Improper Access Control, `EU-AI-ACT EUAIACT.ART14` Human oversight, `NIST-AI-600-1 NIST.GAI.HUMAN` Human-AI configuration, `OWASP-LLM-2025 LLM06` Excessive Agency

## secrets

Credentials written into configuration that gets committed.

### BW-SEC-001

**Live credential stored in plaintext in an agent config**

`severity: HIGH`  `confidence: HIGH`

A credential is written literally into a configuration file rather than referenced from the environment or a secret manager. These files get committed, synced between machines and backed up, and because the agent can read its own configuration, the credential can also end up quoted back into a transcript.

**How to fix.** Replace the literal with an environment reference (`${VAR}`) or a secret-manager URI, then rotate the credential -- it should be treated as disclosed from the moment it was written to disk.

**Maps to.** `CWE CWE-522` Insufficiently Protected Credentials, `CWE CWE-200` Exposure of Sensitive Information, `ISO-42001 ISO42001.A.7.4` Quality of data for AI systems, `NIST-AI-600-1 NIST.GAI.DATA` Data privacy, `OWASP-LLM-2025 LLM02` Sensitive Information Disclosure

## supply-chain

Where a server's code comes from, and whether anyone reviewed it before it ran with the developer's privileges.

### BW-SUP-001

**Server auto-installs an unpinned package on every launch**

`severity: HIGH`  `confidence: HIGH`

The launch command re-resolves a package from a public registry, auto-confirms the install, and pins no version. The code that runs tomorrow is therefore whatever the maintainer -- or whoever compromises the maintainer's account -- publishes tonight. No commit lands in your repository, no build runs, and nothing in the configuration changes, so the change is invisible to every control you already have.

**How to fix.** Pin an exact version in the args (`package@1.4.2`), install the server as a project dependency so a lockfile governs it, or vendor it and launch from a path. Re-pin deliberately after reviewing a diff.

**Maps to.** `CWE CWE-494` Download of Code Without Integrity Check, `CWE CWE-829` Inclusion of Functionality from Untrusted Control Sphere, `ISO-42001 ISO42001.A.10.2` Allocating responsibilities in the AI value chain, `MITRE-ATLAS AML.T0010` ML Supply Chain Compromise, `MITRE-ATLAS AML.T0011` User Execution, `NIST-AI-600-1 NIST.GAI.SUPPLY` Value chain and component integration, `OWASP-LLM-2025 LLM03` Supply Chain

### BW-SUP-002

**Server downloads and executes code at launch**

`severity: CRITICAL`  `confidence: HIGH`

The launch command pipes downloaded bytes into a shell, runs an inline program, or installs straight from a URL or moving VCS reference. There is no artifact to review, no hash to compare and no version to roll back to: what executes is whatever the remote server returns at that instant.

**How to fix.** Replace with a pinned package or a vendored script committed to the repository. If the vendor only ships an installer, run it once manually, review the result, and launch the installed binary by path.

**Maps to.** `CWE CWE-494` Download of Code Without Integrity Check, `CWE CWE-829` Inclusion of Functionality from Untrusted Control Sphere, `CWE CWE-78` OS Command Injection, `MITRE-ATLAS AML.T0010` ML Supply Chain Compromise, `MITRE-ATLAS AML.T0011` User Execution, `NIST-AI-600-1 NIST.GAI.SUPPLY` Value chain and component integration, `OWASP-LLM-2025 LLM03` Supply Chain

### BW-SUP-003

**Package name closely resembles a well-known MCP package**

`severity: HIGH`  `confidence: MEDIUM`

The configured package name is within one or two edits of a widely used package, or borrows a protected publisher scope without being published under it. Both are the standard shapes of a registry impersonation attack, and both survive review precisely because the name looks right.

**How to fix.** Confirm the exact package name against the vendor's own documentation. If the name is genuinely correct, record a waiver so the finding does not recur.

**Maps to.** `CWE CWE-829` Inclusion of Functionality from Untrusted Control Sphere, `MITRE-ATLAS AML.T0010` ML Supply Chain Compromise, `NIST-AI-600-1 NIST.GAI.SUPPLY` Value chain and component integration, `OWASP-LLM-2025 LLM03` Supply Chain

### BW-SUP-004

**Remote MCP endpoint is cleartext, unverifiable or ephemeral**

`severity: HIGH`  `confidence: HIGH`

The server is reached over the network with a transport that cannot be trusted: plain HTTP, a credential in the query string, a bare IP with no certificate identity to verify, or a temporary tunnel domain. An MCP session carries tool definitions inbound and tool arguments outbound, so whoever can intercept or claim the endpoint can both read the agent's data and rewrite its instructions.

**How to fix.** Use HTTPS with a verifiable hostname. Move credentials into an Authorization header. Replace tunnel domains with a stable hostname before this leaves a development machine.

**Maps to.** `CWE CWE-319` Cleartext Transmission, `CWE CWE-295` Improper Certificate Validation, `CWE CWE-598` Sensitive Data in Query String, `EU-AI-ACT EUAIACT.ART15` Accuracy, robustness and cybersecurity, `MITRE-ATLAS AML.T0025` Exfiltration via Cyber Means, `OWASP-LLM-2025 LLM02` Sensitive Information Disclosure, `OWASP-LLM-2025 LLM03` Supply Chain

### BW-SUP-005

**Containerised server runs with isolation removed or a mutable tag**

`severity: MEDIUM`  `confidence: HIGH`

Running an MCP server in a container is a good decision that these flags undo. `--privileged` and `--network=host` return the container to host-level authority, and a mutable tag such as `:latest` means the image contents can change without the configuration changing.

**How to fix.** Drop `--privileged` and host networking; grant specific capabilities and publish specific ports instead. Reference the image by digest (`image@sha256:...`) so the bytes are fixed.

**Maps to.** `CWE CWE-250` Execution with Unnecessary Privileges, `CWE CWE-829` Inclusion of Functionality from Untrusted Control Sphere, `NIST-AI-600-1 NIST.GAI.SUPPLY` Value chain and component integration, `OWASP-LLM-2025 LLM03` Supply Chain, `OWASP-LLM-2025 LLM06` Excessive Agency

### BW-SUP-006

**Server launches a bare binary resolved from the environment**

`severity: MEDIUM`  `confidence: MEDIUM`

The command is neither a path nor a recognised package runner, so what executes depends on the PATH in effect when the agent starts. Anything that can write to an earlier PATH entry -- an installer, a shell profile, another tool's shim directory -- can substitute itself for this server.

**How to fix.** Use an absolute path, or launch through a runner that names the package explicitly.

**Maps to.** `CWE CWE-829` Inclusion of Functionality from Untrusted Control Sphere, `OWASP-LLM-2025 LLM03` Supply Chain

## Writing your own

A rule is a class with metadata and one method. Point a policy at the file and it joins the same pipeline, the same reports and the same exit codes:

```python
from bulwark.core.models import ArtifactKind, Evidence, Severity
from bulwark.core.rulebase import Rule, register


@register
class BannedVendor(Rule):
    id = "ACME-001"
    title = "Server comes from a vendor we do not permit"
    severity = Severity.HIGH
    category = "policy"
    description = "..."
    remediation = "Remove the server and use the approved one."
    frameworks = {"CWE": ["CWE-829"]}

    def check(self, ctx):
        for server in ctx.of_kind(ArtifactKind.MCP_SERVER):
            command = str(server.data.get("command", ""))
            if "bannedvendor" in command:
                yield self.finding(
                    server,
                    evidence=[Evidence(label="command", value=command)],
                )
```

# bulwark.policy.yaml
